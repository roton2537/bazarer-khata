# বাজারের খাতা

একই বাসায় থাকা বা একসঙ্গে খাওয়া মানুষের জন্য বাংলা, মোবাইল-ফার্স্ট শেয়ার্ড বাজার-হিসাবের ওয়েব অ্যাপ।
React + Vite (ফ্রন্টএন্ড) · Supabase (Auth, Postgres, RLS, Realtime) · Vercel (ডেপ্লয়)।

## চালু করার ধাপ

### ১. Supabase
1. [supabase.com](https://supabase.com) এ নতুন প্রজেক্ট খুলুন।
2. **SQL Editor** এ `supabase/migrations/0001_bazar_khata.sql` থেকে শুরু করে `supabase/migrations/` ফোল্ডারের সব SQL ফাইল নম্বর অনুযায়ী চালান। বিদ্যমান ইনস্টলেশনে শুধু নতুন মাইগ্রেশন চালান। নতুন আমন্ত্রণ নাম দিয়ে তৈরি হয় এবং একবার ব্যবহার করা যায়। (অথবা `supabase db push`)
3. নতুন ফোনে ইমেইল ছাড়া প্রবেশের জন্য Supabase Authentication সেটিংসে **Allow anonymous sign-ins** চালু করুন। পুরোনো অ্যাকাউন্টের জন্য **Authentication → Providers → Email** চালু রাখুন।
4. **Authentication → URL Configuration**: *Site URL* এ আপনার Vercel ডোমেইন দিন এবং *Redirect URLs* এ একই ডোমেইন যোগ করুন।
5. **Project Settings → API** থেকে `Project URL` ও `anon public` key নিন।

### ২. Vercel
1. এই ফোল্ডারটি GitHub রেপোতে পুশ করে Vercel-এ Import করুন (Framework: Vite)।
2. Environment Variables: `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` (ঐচ্ছিক: `VITE_VAPID_PUBLIC_KEY`)।
3. Deploy। আমন্ত্রণ-লিংক হবে `https://<আপনার-ডোমেইন>/#/access/<টোকেন>`।

### ৩. পুশ নোটিফিকেশন (ঐচ্ছিক)
1. `npx web-push generate-vapid-keys` দিয়ে কী বানান। Public key টি `VITE_VAPID_PUBLIC_KEY`-তে দিন।
2. `supabase functions deploy notify` এবং secrets সেট করুন: `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`, `WEBHOOK_SECRET`।
3. Dashboard → Database → Webhooks: টেবিল `events`, ইভেন্ট `INSERT`, টার্গেট `notify` ফাংশন, হেডার `x-webhook-secret`।
4. আইফোনে আগে অ্যাপটি “Add to Home Screen” করতে হয়।

পুশ চালু না থাকলেও অ্যাপের ভেতরের “খবর” সবসময় কাজ করে।

## স্থানীয়ভাবে চালানো ও পরীক্ষা
```
cp .env.example .env.local   # মান বসান
npm install
npm run dev
npm test                     # ডেটাবেসের নিয়ম + টাকা-ফরম্যাট পরীক্ষা (লোকাল Postgres/PGlite, Supabase লাগে না)
```

## হিসাবের নিয়ম (সংক্ষেপে)
- সব টাকা মুদ্রার ক্ষুদ্রতম এককে (পয়সা) পূর্ণসংখ্যা হিসেবে রাখা হয়; কোনো ভগ্নাংশ-ত্রুটি নেই।
- বাজারের তারিখে যাঁরা সক্রিয় (যোগদানের দিন ≤ তারিখ, বিরতিতে নয়, ছেড়ে যাননি) তাঁদের মধ্যে সমান ভাগ। ভাগশেষ (১ পয়সা করে) তারিখ-ভিত্তিক ঘূর্ণনে বণ্টিত হয়, তাই যোগফল সবসময় মোটের সমান।
- বিরতি: শুরুর দিন থেকে ভাগ বন্ধ, ফেরার দিন থেকে আবার চালু। গ্রুপ ছাড়লে পরের দিনের বাজার থেকে ভাগ নেই।
- ব্যালেন্স = নিজের বাজার − নিজের ভাগ + নিশ্চিত পরিশোধ দেওয়া − নিশ্চিত পরিশোধ পাওয়া। পরিশোধ প্রাপক নিশ্চিত করলে তবেই ধরা হয়; দ্বিতীয়বার নিশ্চিত করলে কিছু বদলায় না।
- প্রতি মাস আলাদা খাতা। সদস্যরা শুধু চলতি মাসের বাজার সরাসরি লিখতে/বদলাতে পারেন। আগের মাসের জন্য পরের মাসের প্রথম দুই দিন সংশোধনের অনুরোধ → অ্যাডমিনের অনুমোদন।
- অ্যাডমিন মাস শেষ হওয়ার পর হিসাব চূড়ান্ত করেন। চূড়ান্ত মাসের বাজার, ভাগ, পরিশোধ ও রিপোর্ট ডেটাবেস-ট্রিগারে সুরক্ষিত (মালিক হিসেবেও বদলানো যায় না); রিপোর্ট চূড়ান্ত করার মুহূর্তের স্ন্যাপশট হিসেবে সংরক্ষিত।
- ক্লায়েন্ট শুধু SELECT করতে পারে (RLS: শুধু নিজের গ্রুপ)। সব লেখা `SECURITY DEFINER` ফাংশনে, যেখানে সদস্যপদ ও অ্যাডমিন-অনুমতি ডেটাবেসেই যাচাই হয়।

## সীমাবদ্ধতা
- চূড়ান্ত মাসের জন্য আর নতুন পরিশোধ লেখা যায় না; নিশ্চিত না হওয়া পরিশোধ চূড়ান্ত রিপোর্টে “অনিশ্চিত” হিসেবে থাকে, হিসাবে ধরা হয় না।
- অ্যাকাউন্ট মুছে ফেললে সদস্য-রেকর্ড (নাম) ইতিহাসে থাকে, কিন্তু আর পরিশোধ নিশ্চিত/লেখা সম্ভব নয়।

## স্ক্রিন-প্রিভিউ (Supabase ছাড়া)
`npx vite build -c vite.demo.config.js` নমুনা-তথ্যের মক ব্যাকএন্ড দিয়ে স্ক্রিনগুলো বানায় (`dist-demo`)। এটি শুধু ডিজাইন দেখার জন্য, প্রোডাকশনে ব্যবহৃত হয় না।
